# Testing and verification

## Current baseline (2026-09-25)

There is no source code, package manifest, test framework, application build, type checker, linter, or E2E runner. Thus no build, lint, type-check, or application test command exists. These checks are **not run / not applicable**, not passed.

## Future quality gates

Once a stack and requirements are approved, document exact setup and verification commands here. Use unit tests for isolated rules, integration tests for persistence, APIs, and authorization, and E2E tests for critical workflows. Test allowed and denied paths for protected operations. Add practical regression coverage for confirmed defects. Use real persisted data in production flows; test fixtures may be isolated.

Do not mark work complete on UI appearance alone. Record the command, result, and any environment limitation for each verification run.
