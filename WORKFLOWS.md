# Workflows and state machines — planning

Specified sequences below come from the approved source plus approved clarifications C-001 and C-002. Arrows describe intended progression, not permission to skip or reverse a state. Unspecified transitions are marked for owner decision. Every protected transition runs server-side validation, authorization and audit in one business transaction.

| Workflow | Specified path or operations | Controlled transition / unresolved detail |
| --- | --- | --- |
| Lead (R-010) | New → Contacted → Meeting/Discussion → Proposal → Negotiation → Won or Lost. | Lost requires reason; Won may convert to Project. Skips/reopen remain unspecified. |
| Project (R-016) | Draft → Active → Completed → Archived; optional Active ↔ On Hold; Cancelled alternative. | Active needs exactly one Project Lead; On Hold/Cancelled reason. Owner/authorized Team Lead may override configured gates with actor/reason/time/audit. On Hold is optional and resumes to Active; Active may move directly to Completed once required gates pass. Cancelled is terminal. Only the Owner may cancel a Draft/Active/On Hold project after a Project Lead/Team Leader request or on the Owner's initiative; reason, actor/time and audit are required (C-010). C-011 stops unfinished delivery tasks in the same cancellation operation, preserves their history, and allows distinct closeout tasks linked to the Cancelled project. OD-03 asks when vendor/consultant access ends; client access also needs review. |
| Design delivery (R-014) | Measurement → requirements → planning → internal review → client review → corrections → 3D → client approval → working/final drawings → handover. | Template may configure stages/gates; no silent gate bypass. |
| Turnkey delivery (R-015) | Design approval → BOQ → cost approval → materials → procurement → factory → site → quality → snags → handover. | Operational procurement in this app; financial processing in accounting app. Commitments and approvals require authorized humans. |
| Task (R-024–R-026) | Not Started → In Progress → optional Waiting/resume → Submitted Internal Review → In Internal Review → Corrections Required → Internal Approved → Submitted Client Review → In Client Review → Client Revision Required → Client Approved → Completed. | Review steps skipped only when not required. Waiting is optional from an active state; record cause, previous state and resume action. Required reviews still gate completion. Dependency warning allows early start with event. Overdue is derived. C-011 adds terminal Stopped due to project cancellation for unfinished delivery tasks when the Owner cancels their project; existing work/time/review history remains. Completed tasks stay completed. Distinct closeout tasks may be linked to the Cancelled project and follow normal task states; stopped delivery tasks leave active lists, overdue reminders and active capacity. |
| Internal review/correction (R-027–R-029) | Submission → review round → Approved or Corrections Required → correction task → revised submission → new review round. | Reviewer must be authorized/assigned. Preserve each round, comment/markup/version/time/decision/severity/category. Escalation and deadline changes require their separate authority. |
| Client review/approval (R-031–R-034) | Submitted revision → client review → item approval, rejection or revision request; partial approval possible. | Primary Client retains final overall authority; delegation applies only to specified items. Formal approval binds exact item/revision and requires a registered client passkey as well as signature evidence. Portal viewing uses email one-time code. Team Lead/Owner classify revision cause; changes audited. |
| Document/revision (R-030, R-037–R-038) | Working → Submitted → Reviewed → Approved → Issued → Superseded. Internal-review R0/R1/...; client-review CR1/CR2/... | Revision reason required. Newer approved revision makes previous Superseded—Do Not Use. Formal issue creates transmittal; critical issue may require acknowledgement. R is internal review and CR is client review (C-002 Q7); reject/correction paths need an exact transition table. |
| Time (R-041–R-042) | Timer Start ↔ Pause/Resume → Stop; manual entry allowed. | Concurrent timers prevented/detected. Existing entry corrections append old/new/reason/editor/time. Lock after manager approval/export; corrections create history and idempotent re-export. |
| Leave (R-049–R-050) | Request → authorized one/multilevel decision → approved leave reduces capacity and triggers affected-task analysis. | Work from Home changes attendance/schedule without consuming leave. January–December annual entitlement is credited upfront per Owner-configured Branch policy; new hires and Branch transfers use calendar-day proration. Up to five unused days carry into the next year and expire at that year's end. Cancellation/reversal must preserve ledger history; emergency leave runs impact analysis immediately. |
| Attendance (R-051) | Check-in → check-out; late/early/missing derived. | Site check-in uses location + QR + selfie. Missing evidence/connectivity permits provisional check-in with reason and manager review; site selfies expire ninety days after capture under C-003/C-009; controlled expiry still needs legal/contract validation. |
| Skill/training (R-044–R-045, R-055–R-057) | Training assigned → completed/assessed → skill recommendation → Team Lead/Owner approval → official rating change. | Completion alone never upgrades skill. SOP publication/version/acknowledgement stays separate. |
| Snag (R-070) | Open → Assigned → In Progress → Ready for Verification → Verified → Closed. | Failed verification may reopen; assigned/verification authority needs policy. |
| Deletion (R-081) | Employee request → Team Lead/Owner decision → hide from normal view if approved. | Protected evidence follows C-003/C-009 retention. Expiry schedules deletion with advance Owner notice; documented holds suspend it. Backup lifecycle and deletion proof require design/legal review. |
| External CAD share (C-006) | Owner verifies assigned vendor/consultant and exact file revision → creates native MinisCloud link with seven-day expiry and extraction code → records recipient/link metadata → cancels on access loss or expiry. | Only Owner issues/cancels; clients never receive CAD; link can be forwarded, and installed NAS controls need validation. |
| Automation/AI (R-054, R-083, R-089) | Event/recommendation → proposed high-impact action → human approval → domain command. | Low-risk notification/report may run automatically; high-impact action cannot bypass ordinary permissions or approval. |
| Employee exit (R-092) | Access active → exited/revoked. | Historical project/task/audit references remain; exact HR states unresolved. |

Each transition later needs a transition table of from/to, actor/scope, preconditions, effects, audit/event, invalid-transition test and recovery behavior. Do not infer missing arrows from the displayed default sequences.
