# Workflows and state machines — planning

Specified sequences below come from the approved source plus approved clarifications C-001–C-024. Arrows show default progression; C-017 and C-019 define explicit lead-stage exceptions. Unsupported transitions are denied until a slice specifies their guards and tests. Every protected transition runs server-side validation, authorization and audit in one business transaction.

| Workflow | Specified path or operations | Transition control and exceptions |
| --- | --- | --- |
| Lead (R-010) | New → Contacted → Meeting/Discussion → Proposal → Negotiation → Won or Lost. | Lost requires reason; Won may convert to Project. C-017 allows a scoped, authorized handler to jump forward with reason and audited skipped stages; skips are not completed steps. C-018 keeps Lost terminal; a returning enquiry starts a new linked lead with separate stage history and reports. C-019 allows a scoped handler to move a nonterminal lead to an earlier nonterminal stage with reason; prior stage history and activities remain. Won/Lost are not reopened by this rule. |
| Project (R-016) | Draft → Active → Completed → Archived; optional Active ↔ On Hold; Cancelled alternative. | Active needs exactly one Project Lead; On Hold/Cancelled reason. C-024 moves an Active project led by an exiting employee On Hold immediately, preserves former lead history, pauses new delivery decisions, and requires the Owner to appoint an eligible replacement before audited resume to Active. Owner/authorized Team Lead may override configured gates with actor/reason/time/audit. On Hold is optional and resumes to Active; Active may move directly to Completed once required gates pass. Cancelled is terminal. Only the Owner may cancel a Draft/Active/On Hold project after a Project Lead/Team Leader request or on the Owner's initiative; reason, actor/time and audit are required (C-010). C-011 stops unfinished delivery tasks in the same cancellation operation, preserves their history, and allows distinct closeout tasks linked to the Cancelled project under C-016 Project Lead/authorized Team Leader approval. C-012 ends vendor/consultant project access at cancellation and requires active native CAD links to be revoked and recorded before finalization. C-013 leaves only read-only access to previously issued client PDFs/images and own approval history; C-014/C-015 end each client's project access on the date the Owner sets at cancellation, with an audited Owner extension; no shared period applies. |
| Design delivery (R-014) | Measurement → requirements → planning → internal review → client review → corrections → 3D → client approval → working/final drawings → handover. | Template may configure stages/gates; no silent gate bypass. |
| Turnkey delivery (R-015) | Design approval → BOQ → cost approval → materials → procurement → factory → site → quality → snags → handover. | Operational procurement in this app; financial processing in accounting app. Commitments and approvals require authorized humans. |
| Task (R-024–R-026) | Not Started → In Progress → optional Waiting/resume → Submitted Internal Review → In Internal Review → Corrections Required → Internal Approved → Submitted Client Review → In Client Review → Client Revision Required → Client Approved → Completed. | Review steps skipped only when not required. Waiting is optional from an active state; record cause, previous state and resume action. Required reviews still gate completion. Dependency warning allows early start with event. Overdue is derived. C-011 adds terminal Stopped due to project cancellation for unfinished delivery tasks when the Owner cancels their project; existing work/time/review history remains. Completed tasks stay completed. Distinct closeout tasks may be linked to the Cancelled project and follow normal task states; stopped delivery tasks leave active lists, overdue reminders and active capacity. |
| Internal review/correction (R-027–R-029) | Submission → review round → Approved or Corrections Required → correction task → revised submission → new review round. | Reviewer must be authorized/assigned. Preserve each round, comment/markup/version/time/decision/severity/category. Escalation and deadline changes require their separate authority. |
| Closeout work on Cancelled project (C-011/C-012/C-016) | Assigned Project Lead or explicitly authorized Team Leader approves a separately identified closeout task with reason, owner, scope and due date; if a vendor/consultant is needed, grants item/work-package-scoped portal access with an end time; task completion or expiry ends that access. | Cancelled remains terminal; stopped delivery tasks do not reopen. The approver must hold current project authority; a job title alone is insufficient. The Owner alone may issue a native CAD link, grant cross-branch staff access or make other protected Owner-only decisions. All decisions and revocations are audited. |
| Client review/approval (R-031–R-034) | Submitted revision → client review → item approval, rejection or revision request; partial approval possible. | Primary Client retains final overall authority; delegation applies only to specified items. Formal approval binds exact item/revision and requires a registered client passkey as well as signature evidence. Portal viewing uses email one-time code. Team Lead/Owner classify revision cause; changes audited. On project cancellation, pending client review/approval decisions become Withdrawn due to project cancellation with history retained; no further client comments, reviews or approvals, while C-013 issued-record read-only access remains only until that client's C-015 expiry or Owner revocation. |
| Document/revision (R-030, R-037–R-038) | Working → Submitted → Reviewed → Approved → Issued → Superseded. Internal-review R0/R1/...; client-review CR1/CR2/... | Revision reason required. Newer approved revision makes previous Superseded—Do Not Use. Formal issue creates transmittal; critical issue may require acknowledgement. R is internal review and CR is client review (C-002 Q7); correction paths use a new immutable revision and review round as specified below. |
| Time (R-041–R-042) | Timer Start ↔ Pause/Resume → Stop; manual entry allowed. | Concurrent timers prevented/detected. Existing entry corrections append old/new/reason/editor/time. Lock after manager approval/export; corrections create history and idempotent re-export. |
| Leave (R-049–R-050) | Request → authorized one/multilevel decision → approved leave reduces capacity and triggers affected-task analysis. | Work from Home changes attendance/schedule without consuming leave. January–December annual entitlement is credited upfront per Owner-configured Branch policy; new hires and Branch transfers use calendar-day proration. Up to five unused days carry into the next year and expire at that year's end. C-022: the employee may request cancellation, but only the same approval level as the original leave may approve it. Pending cancellation has no balance/capacity effect; approval applies a separate unused-leave reversal, recalculates capacity and alerts affected managers/task owners without silently undoing handovers. Original decision and ledger history remain. Emergency leave runs impact analysis immediately. |
| Attendance (R-051) | Check-in → check-out; late/early/missing derived. | Site check-in uses location + QR + selfie. Missing evidence/connectivity permits provisional check-in with reason and manager review; site selfies expire ninety days after capture under C-003/C-009; controlled expiry still needs legal/contract validation. |
| Skill/training (R-044–R-045, R-055–R-057) | Training assigned → completed/assessed → skill recommendation → Team Lead/Owner approval → official rating change. | Completion alone never upgrades skill. SOP publication/version/acknowledgement stays separate. |
| Snag (R-070) | Open → Assigned → In Progress → Ready for Verification → Verified → Closed. | C-020: assigned Project Lead/explicitly authorized Team Leader appoints a project-scoped verifier distinct from the fixer; only the named verifier may pass/fail the check. Failure records evidence and returns the same snag to In Progress. C-021: only the assigned Project Lead or explicitly authorized Team Leader may make the separate Verified → Closed decision after a current passed check; record closer/time and keep verification evidence. |
| Deletion (R-081) | Employee request → Team Lead/Owner decision → hide from normal view if approved. | Protected evidence follows C-003/C-009 retention. Expiry schedules deletion with advance Owner notice; documented holds suspend it. Backup lifecycle and deletion proof require design/legal review. |
| External CAD share (C-006) | Owner verifies assigned vendor/consultant and exact file revision → creates native MinisCloud link with seven-day expiry and extraction code → records recipient/link metadata → cancels on access loss or expiry, including project cancellation. | Only Owner issues/cancels; on project cancellation, Owner verifies active link revocation in MinisCloud and records it before the project transition is finalized (C-012). Clients never receive CAD; link can be forwarded, and installed NAS controls need validation. |
| Automation/AI (R-054, R-083, R-089) | Event/recommendation → proposed high-impact action → human approval → domain command. | Low-risk notification/report may run automatically; high-impact action cannot bypass ordinary permissions or approval. |
| Employee exit (R-092) | Access active → exited/revoked. | C-023 revokes access immediately and moves unfinished tasks to Waiting with needs-reassignment reason, preserving prior state/owner/review history. A scoped manager selects each replacement before resuming; completed tasks remain unchanged. C-024 holds Active projects led by the exiting employee until the Owner appoints a replacement; HR state detail is a technical design task. |

## Transition rules for implementation

These technical rules derive from the approved source and addenda. Each slice must encode from/to, actor, precondition, effect, audit/event and invalid-transition tests before implementation. A technical rule does not grant a new business permission.

| Record | Allowed transition and guard | Evidence and exception behavior |
| --- | --- | --- |
| Project | Draft → Active requires one eligible Project Lead and activation gates. Active ↔ On Hold requires reason; C-024 lead exit moves Active → On Hold immediately and blocks new delivery decisions until Owner replacement and gate-checked resume. Active → Completed requires completion gates; Completed → Archived preserves records. Draft/Active/On Hold → Cancelled requires C-010 Owner decision and C-011–C-015 preconditions. | Cancelled and Archived are terminal. A cancellation request or unconfirmed NAS link revocation is not a final transition. Override cannot erase protected evidence. |
| Task | The displayed review path is a configured default. Waiting stores previous state and reason; resume requires an eligible owner and applicable review gates. C-023 forces unfinished tasks to Waiting on owner exit, and C-011 stops unfinished delivery tasks on project cancellation. | Prior submissions, review rounds, approvals, time and owner history remain immutable. A stopped delivery task cannot resume; closeout work is a new C-016 task. |
| Document revision and review round | A newly numbered R or CR revision begins Working; submission freezes its blob and enters Submitted. An assigned reviewer records a Reviewed decision: approval can advance that exact revision to Approved; correction/rejection leaves it Reviewed with a Corrections Required outcome; after the authorized correction response and, for a client request, Team Leader/Owner classification, a new Working revision and review round are created. | Do not put a rejected blob back into Working or overwrite it. Client rejection or partial approval stays bound to exact item/revision; approved unaffected items remain approved. A new revision must pass required gates. |
| Formal document issue | Only an authorized actor moves an Approved exact revision to Issued by creating a transmittal. A newer approved revision may designate the prior current revision Superseded—Do Not Use, while its earlier issue/approval evidence remains. | Superseded material stays retrievable to authorized users and is never silently replaced in old transmittals. No Issued or Superseded revision returns to Working; corrections create a new revision. |
| Leave | Request → Approved or Denied through configured approval level. C-022 adds a separate cancellation request; only same-level approval moves the eligible unused portion to Cancelled and appends compensating balance/capacity entries. | Pending or denied cancellation changes nothing. Used leave, original approval and task handovers remain historical; no silent balance rewrite. |
| Site snag | Open → Assigned → In Progress → Ready for Verification → Verified → Closed. The C-020 named independent verifier passes or fails the current repair; failure returns to In Progress with attempt evidence. C-021 management authority separately closes a currently Verified snag. | Neither fixer nor unassigned viewer can verify. A failed or stale check cannot support closure; rework keeps earlier attempts. |
| Employee exit | Active access → revoked/exited immediately. C-023 task waits and C-024 project holds commit with exit evidence; sessions and grants stop authorizing requests. | Historical references retain stable IDs and display snapshots. Rehire, if later supported, uses a new dated employment period and active credentials rather than restoring old sessions. |

Offline site commands retain a stable client ID, base record version and idempotency key. Independent new observations/photos may append once. If the same record changed on the server, the upload is held in a conflict queue; the user can keep the server version or submit an amended new version after seeing both. No queued command overwrites a newer server version automatically.
## S06 implemented workflows

Granted actors create NEW leads in an authorized branch, record interactions, and change stages with optimistic versions. Skips, backward moves and Lost require reasons. Won/Lost remain terminal; returning enquiries create separate linked leads under creation and prior-view authority. Owner edits shared clients/contacts with reason and version, preserving contact identities. Source managers use organization-scoped authority to add or activate/deactivate sources with reason and expected timestamp. Each command persists audit/event/outbox evidence; no automatic customer message or project creation is performed.
