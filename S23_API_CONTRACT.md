# S23 settled bounded API handoff

All routes below are internal staff `/api/v1/performance`, use the ordinary session cookie, `no-store`, same-origin CSRF for POST and backend current subject/source authorization. CLIENT/EXTERNAL identities are denied. No active numeric defaults are seeded. Policy figures entered into tests are fictional Owner setup.

## DTOs

`Record = { id, organizationId, kind, state, version, employeeId:null|string, projectId:null|string, data:object, createdById, createdAt, updatedAt }`. Kinds POLICY/ASSIGNMENT/SCORE/HEALTH/DELAY/CYCLE. State POLICY=DRAFT|APPROVED, CYCLE=OPEN|FINALIZED, other immutable records=ACTIVE. Cycle changes retain versions/history; immutable snapshots/attributions are never rewritten.

`Policy = { family:"EMPLOYEE"|"LEADER"|"DESIGN"|"TURNKEY", groupKey:string, label:string, effectiveFrom:"YYYY-MM-DD", components:[{metric:string,weight:number,min:number,max:number,direction:"HIGHER"|"LOWER",required:boolean}], attendanceMaxWeight:number, efficiencyMaxWeight:number, strengthAt:number, weaknessBelow:number, thresholds:{criticalBelow:number,delayedBelow:number,atRiskBelow:number} }`. Formula: weighted mean of bounded linear normalization to 0–100; explicitly approved optional missing components are excluded and weights renormalized; required missing inputs produce INSUFFICIENT_EVIDENCE/no score. Employee renormalization also requires available quality weight to remain greater than speed, and attendance/efficiency percentages to remain within the approved caps; otherwise no score. Every selected component's metric/raw value/normalization/evidence is displayed before approval and retained afterward. Weights sum to 100; max>min; quality weight exceeds raw-speed weight; configured attendance/efficiency caps apply. All values require Owner entry. Health groupKey equals family; employees and leaders use explicit Owner-defined groups. Generation periods crossing an approved effective policy/group change require separate snapshots.

Metric catalogue entries `{key,label,families,category,unit,description}`. Available EMPLOYEE metrics: TASK_ON_TIME, REVIEW_FIRST_PASS, REVIEW_CORRECTION_FREE, TIME_EFFICIENCY, ATTENDANCE_VERIFIED. LEADER: LEADER_REVIEW_TURNAROUND, LEADER_EXTENSION_TURNAROUND, LEADER_ALLOCATION_COVERAGE. Project DESIGN/TURNKEY: PROJECT_TASK_ON_TIME, PROJECT_MILESTONE_COMPLETION, PROJECT_REVIEW_FIRST_PASS, PROJECT_PENDING_DECISIONS, PROJECT_SCOPE_CHANGE_COUNT, PROJECT_DELAY_DAYS, PROJECT_WORKLOAD_ALLOCATION, PROJECT_WORKLOAD_RISK; TURNKEY additionally SITE_PROGRESS, SITE_QUALITY, SITE_SNAG_CLOSURE. Counts/ratios come from existing persisted sources. Workload risk uses current schedule-derived available/allocated capacity and existing Owner-approved WFM thresholds, retaining source basis IDs/versions; no schedule/policy yields missing evidence. Training/skills/SOP metrics are unavailable. Turnaround is lower-better; percentages are higher-better except pending decisions/scope changes/delay/overload risk. Owner still explicitly sets normalization direction/range.

`Snapshot.data = {family,from,to,policyId,policyVersion,groupKey,status:"SCORED"|"INSUFFICIENT_EVIDENCE",score:number|null,healthStatus:null|"On Track"|"At Risk"|"Delayed"|"Critical",components:[{metric,label,raw:number|null,normalized:number|null,weight,evidence:[{kind,id,version,description,values:object}]}],missing:string[],excluded:[object],explanation:string[],strengths:string[],weaknesses:string[],repeatedMistakes:[{category:string,reviewRoundIds:string[]}],improvementActions:string[],operational:{completedTasks?:number,eligibleOnTimeTasks?:number,reviewRounds?:number,scheduleVarianceDays?:number|null,scopeChangeImpact?:object[],workloadRisk?:object[],personallyHandledReviews?:number,personallyPreparedAllocations?:number},previousSnapshotId:string|null,scoreChange:number|null,changeExplanation:string[],unavailable:["Training","Skills","SOP recommendations"]}`. Generated insufficient snapshots preserve truthful evidence and null score. Existing snapshots remain unchanged by later policy/source changes. Leader snapshots retain only personally controlled leader inputs and summaries, avoiding unrelated employee-task evidence. The assigned independent reviewer can read their exact personally handled round under current project/review.decide and revision/Confidential authority; ordinary task sources and snapshot-generation authority remain unchanged. Source references shown only under current access. Required project workload/delay inputs become unavailable when eligible source records are inaccessible, rather than scoring an incomplete subset. Source access loss returns ACCESS_RESTRICTED with null score and redacted components; it never rewrites the underlying snapshot.

`Delay.data = {cause:"INTERNAL_TEAM"|"CLIENT"|"CONSULTANT"|"VENDOR"|"FACTORY"|"PROCUREMENT"|"MATERIAL"|"SITE_CONDITION"|"APPROVAL"|"SCOPE_CHANGE"|"OTHER",days:number,sourceKind:"TASK_STATUS"|"TASK_DATE"|"REVIEW_ROUND"|"SITE_HISTORY"|"PROJECT_SCOPE",sourceId:string,employeeId:string|null,external:boolean,from:string,to:string,summary:string,supersedesId:string|null}`. Days are explicit equivalent delay-day allocations reviewed by Owner, not inferred elapsed calendar days; each source has one current attribution, corrections supersede immutable prior evidence. Totals are sum of explicitly allocated days with source deduplication; external exclusion requires Owner review. Cause INTERNAL_TEAM cannot be external. Link subject to the source's project/task/employee.

`Cycle.data = {frequency:"WEEKLY"|"MONTHLY"|"QUARTERLY"|"ANNUAL",from,to,scoreId:string|null,goals:string[],developmentActions:string[],comments:[{actorId,text,at}],acknowledgements:[{actorId,text,at}],finalizedBy:null|string,finalizedAt:null|string}`. Acknowledgement is own only and never approves a score. Owner finalization requires a grounded current score snapshot or an explicit insufficient-evidence snapshot.

## GET

- `/context` returns `{owner:boolean,employeeId:null|string,employees:[{id,label,teamId,branchId,canManage:boolean}],projects:[{id,label,deliveryType}],policies:Record[],assignments:Record[],metrics:Catalogue[],unavailable:string[]}`. Employees contain own and explicitly managed targets; ordinary staff receive no other employee identities/policies unrelated to their group. Project list uses current project access.
- `/employees/:id` returns `{employee:{id,label},snapshots:Record[],cycles:Record[],groupAssignments:Record[],teamAverage:number|null,relativeToAverage:number|null,canManage:boolean,unavailable:string[]}`. Anonymous average uses compatible latest scored EMPLOYEE snapshots for currently permitted own-team cohort; no names/counts/rankings in employee responses. LEADER snapshots separate from EMPLOYEE. Management may view permitted named targets through context.
- `/projects/:id` returns `{project:{id,label,deliveryType},snapshots:Record[],delays:Record[],delayTotalDays:number,delayByCause:[{cause,days}],canManage:boolean,unavailable:string[]}`. Current scoped project authority applies; delay creation/review remains Owner-only.

## POST `/commands`

Every command is `{commandId:uuid,reason:string,operation:string,...fields}`. Reused exact command returns original record after current authorization; changed payload rejects. UUID record IDs/employee/project/source IDs. Strict server DTOs. All operations return `Record`.

- `POLICY_CREATE`: `policy:Policy`; Owner only, creates DRAFT.
- `POLICY_APPROVE`: `id,expectedVersion`; Owner only; prospective effectiveFrom, validates all policy definitions, appends approval version and freezes.
- `ASSIGN_GROUP`: `employeeId,family:"EMPLOYEE"|"LEADER",groupKey,effectiveFrom`; Owner only, explicit dated assignment to an existing approved group. No automatic JobRole mapping.
- `EMPLOYEE_SNAPSHOT`: `employeeId,family:"EMPLOYEE"|"LEADER",from,to`; Owner or current explicitly scoped performance manager; current assigned approved policy. No matching approved policy returns 409 and persists no score.
- `PROJECT_SNAPSHOT`: `projectId,from,to`; Owner or current explicitly scoped project performance manager; deliveryType selects DESIGN/TURNKEY policy. No matching approved policy returns 409.
- `DELAY_RECORD`: `projectId,delay:Delay` (supersedesId optional/null; employeeId optional/null); Owner only, validates real source membership and cause/duration, corrections append new record.
- `CYCLE_CREATE`: `employeeId,frequency,from,to,scoreId:string|null,goals:string[],developmentActions:string[]`; Owner or scoped manager; linked score must match employee and period.
- `CYCLE_COMMENT`: `id,expectedVersion,text:string,goals:string[],developmentActions:string[]`; current scoped manager; OPEN only; comments and changed goals/actions retained in version history.
- `CYCLE_ACKNOWLEDGE`: `id,expectedVersion,text:string`; target employee only, finalized cycles permitted; acknowledgement is immutable and updates only separate acknowledgement history.
- `CYCLE_FINALIZE`: `id,expectedVersion`; Owner only, OPEN only, requires matching frozen snapshot. If creation preceded any snapshot, finalization atomically binds the latest exact employee/period EMPLOYEE snapshot (including a truthful insufficient-evidence snapshot) and records that binding; no available exact snapshot rejects finalization.

Permissions: `performance.manage` evaluated on target current home TEAM/BRANCH scope with current reporting-tree reach; own view is allowed subject to explicit `performance.view` deny, management does not follow job title. Project health view requires ordinary current project assignment/view; generation requires `performance.manage` with project branch scope and current project lead or explicitly scoped Team Leader management authority. Owner retains explicit review/approval/finalization actions. Own acknowledgement also checks current own performance visibility. Source evidence is redacted on read where source permission is absent; averages/derived scores do not disclose inaccessible records. Existing read-only REV/DOC/APR/WFM ports retain exact Confidential revision, typed approval and workforce-capacity permissions.
