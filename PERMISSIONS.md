# Proposed authorization model — no enforcement implemented

Approved source: R-004–R-009, R-027–R-039, R-075–R-081, R-087–R-099. Approved C-001: Organization → Branch → Team → Employee, no Brand permission scope; one owning branch per project; employees may work across branches only with explicit assignment. Job role, reporting relation within Branch/Team, and permission grant remain separate. The matrix below is an initial baseline derived from the source, not hard-coded job titles or a finalized grant list.

## Effective access rule

Authenticate and verify an active server-side session; determine organization, branch/team/project membership and explicit grants; then authorize resource + action + scope + conditions. Default deny. Explicit deny takes precedence over allow as a technical safety rule. A project assignment can grant work-specific cross-branch access, but does not grant access to all branch projects, confidential files, employee performance or permission management. Recheck authorization at download/stream time and on every mutation. For cancelled-project client reads, also check that client's C-015 expiry and any Owner-approved extension on every request; a scheduled job is not the security boundary. Forced logout or grant revocation invalidates future access immediately. Owner workflow override records actor, reason and time but cannot violate integrity or immutable evidence.

All client portal accounts receive PDF and image files only under C-002 Q13; this applies to Primary and Additional Clients. C-013 narrows cancelled-project access to previously issued items and own approval history; the Owner may revoke an account's grant. C-014/C-015 make each client's cancelled-project read-only grant expire on its own Owner-set date, subject to audited Owner changes or extensions; no shared period applies. Native NAS CAD links are permitted only for explicitly assigned vendors and consultants under C-006; clients never receive CAD links. Only the Owner issues links and cancels active links immediately when recipient access ends; C-012 makes project cancellation such an access-ending event and requires confirmed native-link revocation before finalization. Because a native link can be forwarded, expiry and extraction code reduce but cannot eliminate this risk.

## Permission names and scopes

Use resource.action names such as lead.stage_change, project.view, project.manage, task.assign, task.reassign, review.decide, document.download, document.issue, client_approval.decide, employee.manage, permission.manage, performance.view_own, performance.view_team, audit.view, automation.manage. Scope vocabulary: own, assigned, team, branch, project, organization, explicit item. Conditions may include membership, document classification, workflow state, delegated approval and expiry. Configure role bundles dynamically; store explicit overrides separately from job role and hierarchy.

Security tests must cover allowed and denied behavior, guessed IDs, cross-branch assigned versus unassigned access, file direct URL replay, portal-to-internal escalation, revoked sessions, stale grants, confidential folders, unpublished galleries and AI read contexts. Never rely on frontend filtering.

## Decision dependencies

C-017 permits a forward lead-stage jump only for an actor with lead.stage_change and current scope for that lead; it requires a reason and audited skipped-stage evidence. Granting a job title alone never grants this action. C-018 returning-lead creation requires the new-lead creation grant and permission to view the prior Lost lead before linking or showing its history. A cross-branch link does not expand either lead's visibility. C-019 permits backward moves only while the lead remains nonterminal and requires the same scoped lead.stage_change grant, reason and immutable history; it does not undo formal decisions. C-020 lets the assigned Project Lead or explicitly authorized Team Leader appoint or reassign the verifier for a project snag, with reason and audit. The appointment grants only the named snag verification action to a person who already has appropriate project access; it does not grant cross-branch project access. Self-verification by the fixer is denied. C-021 permits only the assigned Project Lead or a Team Leader with an explicit project snag-closure grant to move a currently Verified snag to Closed after checking its passed verification; assignment as verifier alone is insufficient. A person holding both roles must make a separate audited closure decision. C-023 revokes a departing employee's sessions and grants immediately; their unfinished tasks enter Waiting and remain inaccessible to them. An authorized manager must explicitly grant an eligible replacement owner before any task resumes, with history and audit; cross-branch reassignment still needs Owner-granted access. C-024 moves Active projects led by an exiting employee to On Hold; that person loses decision authority immediately. Only the Owner appoints an eligible replacement for this exit hold before the project can resume Active; pending reviews keep evidence but cannot receive new delivery decisions during the hold. Existing authorized read access to issued records continues under its ordinary grant; the hold does not widen access. C-022 lets an employee request cancellation of their approved leave; only an approver at the original required management level may approve the reversal. Pending requests do not restore balance or capacity; decision and effects are audited.

C-002 makes the Owner the only authority for cross-branch project grants and retains final overall client approval with the Primary Client. C-006 resolves vendor/consultant CAD issuance and revocation controls. C-010 makes project cancellation Owner-only; C-011 stops unfinished delivery tasks and permits separately identified closeout tasks under ordinary authorization. C-012 ends vendor/consultant project access on cancellation; C-013 fixes read-only client portal scope after cancellation; C-014/C-015 require per-client automatic expiry and Owner-approved extensions; C-016 delegates ordinary closeout task and narrow temporary external-access approval to the assigned Project Lead or explicitly authorized Team Leader. Owner-only CAD and cross-branch grant authority remains. The source does not authorize automatic permission inheritance from a job title. See REQUIREMENT_QUESTIONS.md.
