The provider accepts a strict bounded evidence object, not arbitrary database queries or tools. Source text is untrusted data, never an instruction to widen access or execute commands. Validate output type, size, candidate identities and evidence references against the authorized request; reject fabricated citations and unsupported actions. Reauthorize source manifests before returning retained content and again before recording a decision. Access loss redacts/denies presentation without mutating retained history.

## Persistence and migration design

Proposed AI-owned additive tables are AiRun, AiDecision and AiReceipt. AiRun retains organization/requester/project scope, typed capability, provider/version, canonical input digest, structured authorized source manifest, result and creation audit/event identity. AiDecision retains run, actor, accepted/rejected/override selection, mandatory reason, optional exact domain outcome reference and audit/event identity. AiReceipt binds actor, command, canonical payload digest and retained result. Final field names/constraints require Sol schema review before implementation.

Organization-consistent foreign keys, immutable result/decision guards and unique actor/command receipts enforce retention and duplicate replay. Changed reuse conflicts. A later outcome is appended and verified through its owning public source port; it never claims that the AI finalized the action. Canonical audit/events/outbox commit atomically. No expiry/purge policy is invented. S27 migration115 is additive after accepted S18 migrations110–114 and source109; existing applied migrations and original rows stay unchanged. If APR is integrated, register a distinct canonical AI recommendation type with current-source canView/canDecide checks, and record only nonbinding review; never reuse AUT's type to change ownership.

Decision invariants: summary decisions forbid assignment selection. Assignment ACCEPTED and OVERRIDDEN decisions require a typed currently eligible selection; REJECTED decisions forbid selection. Assignment scope derives from the exact task and a mismatched supplied projectId is rejected. An outcome must bind the original run task and a prior ACCEPTED/OVERRIDDEN decision; the owning port verifies current persisted owner/collaborator/reviewer state. Reauthorize each retained manifest entry before exposing content. Candidate staleness may be disclosed only while all retained source facts remain authorized; source-access loss denies or redacts the result.
