# S10 recurrence — R-020.b / R-021.c

S10 is Owner-authorized and IN PROGRESS. This vertical increment implements recurrence for persisted RECURRING source tasks. S11 and later remain unauthorized. Approved source sections 20–21 supply recurring task type/fields; the Owner settled daily/weekly/monthly frequency, organization timezone initially Asia/Kolkata, one occurrence per scheduled date, skipped downtime dates, and suspended generation for inactive/exited owners or non-Active linked projects. Monthly dates 29–31 clamp to the last day of a short month while retaining the original anchor day.

The current primary owner, Owner or existing scoped task manager may configure, pause or resume a source rule with a reason and current task/rule versions. Collaborators, title-only managers, unrelated scopes and inactive actors cannot. Configure explicitly supplies the first occurrence as a future calendar date in the organization's current timezone. A source may finish its own task without ending the schedule. Pause/resume is separate and audited; resume retains the anchor and begins with the next scheduled date strictly after the current local date. Worker generation rechecks the latest configuration actor's current authority, source's current owner/collaborators and project eligibility and fails closed after permission revocation.

The rule persists one source, frequency, anchor date, manual paused state, version and effective first date. Immutable change history records before/after, actor, reason, version and time. Occurrences have a unique rule/date and unique generated-task link. Generated tasks begin NOT_STARTED with target date equal to the scheduled date and copy current title, description, priority, primary owner, collaborators with estimates, task estimate, tags, checklist and review requirement. Project association is retained. They do not inherit committed dates, dependencies, start dates or a recurrence rule; generation never resumes, completes or bypasses review of existing work.

The worker considers only today's date in each organization's configured timezone. It creates no missed-date backlog. Concurrent workers lock the rule and unique occurrence key; task, occurrence, audit/event/outbox commit atomically. Audit failure must leave no generated task or occurrence, allowing a valid retry. Inactive owner, no-longer-authorized configuration actor, invalid collaborators or inactive project suspend generation without silently changing the manual pause setting. A rule change requires a future first date, so it cannot backfill or replace an already generated occurrence. A timezone change affects subsequent local-date evaluation, with the same rule/date uniqueness.

API: `GET /api/v1/tasks/:id/recurrence` returns `{ rule, history, capabilities: { configure, pause, resume }, timezone }`. `PUT` at that path accepts strict `{ expectedTaskVersion, expectedVersion, frequency: DAILY|WEEKLY|MONTHLY, firstOccurrenceDate, reason }`; expectedVersion is 0 only when no rule exists. `POST /:id/recurrence/pause` and `/resume` accept `{ expectedTaskVersion, expectedVersion, reason }`. Mutations enforce active sessions, same origin, CSRF, strict inputs and transactional current authority. Histories are visible only through existing task access. The worker has no externally exposed generate endpoint.
