## Internal actor and request rules

Use ordinary staff/Owner cookie session, Owner identity-readiness check, no-store responses. Every mutation requires matching configured Origin and x-csrf-token. Pass current sessionId with ProjectActor into service for post-lock session reauthorization. External/client portal identities denied. Command identity is UUID commandId plus reason (3–1000 characters); exact replay returns retained result, changed command input conflicts. Versioned changes require expectedVersion positive integer.

## Calendar service/controller contract

IntegrationService.actor(accountId, sessionId?) obtains ProjectActor/session context; authenticated controllers derive account from IdentityService, never body.

- GET /integrations/setup → { owner, projects: [{ id, title, canManageEvents }], events: CalendarEventView[], subscription: { active: boolean, id?: string, createdAt?: string }, connectorOptions, websiteConnectors, deliveries, locations }. Approved connector/location shapes are defined below; Owner-only collections are empty for other internal actors.
- GET /integrations/calendar → { events: CalendarProjection[] }. Projection: { uid: string, kind: TASK_DEADLINE|MILESTONE|REVIEW_ASSIGNMENT|MEETING|SITE_VISIT, label: string, start: string, end?: string, allDay: boolean, sequence: number, updatedAt: string, cancelled: boolean }. Generic labels only; opaque stable UID; no source/project IDs, names, notes, contacts or location in exports.
- GET /integrations/calendar.ics → same current authorized projection serialized as text/calendar; charset=utf-8, attachment sense-calendar.ics, no-store. Controller calls IntegrationService.calendar(actor); serializer is pure and handles CRLF, UTF-8 byte folding, escaping and date-only/UTC instants.
- POST /integrations/calendar/subscription { commandId, reason } → { id, token, relativeUrl, createdAt }. Token returned only on creation/rotation; persisted hash only. Rotation revokes all prior capability URLs for that account. Persist replay result must not store plaintext token; identical replay returns safe retained status and explicitly directs creation of a new command to rotate if the one-time token was lost.
- DELETE /integrations/calendar/subscription { commandId, reason } → { revoked: true }.
- Public GET /integrations/calendar/subscriptions/:token.ics → current active capability account's same minimal projection. PublicRoute applies only here; service performs token hash lookup, current account/source reauthorization and revoked denial. Token never in logs/audit. Unknown/revoked tokens receive a safe not-found response and no-store. Captured/imported calendar copies cannot be remotely retracted.
- POST /integrations/calendar/events { commandId, reason, kind: MEETING|SITE_VISIT, projectId?: UUID, startAt: ISO datetime with offset, endAt: ISO datetime with offset } → CalendarEventView. End must follow start. No attendees/notifications/external invitations. Personal events creator-only; project events require current existing project.manage, explicit assignment/cross-branch scope. New project event requires ACTIVE project. No event creates assignment/access.
- PUT /integrations/calendar/events/:id { commandId, reason, expectedVersion, startAt, endAt } → CalendarEventView. Current management/creator scope; immutable retained history; canceled events cannot edit.
- POST /integrations/calendar/events/:id/cancel { commandId, reason, expectedVersion } → CalendarEventView with state CANCELLED. Preserve row/history.

CalendarEventView: { id, kind, projectId: string|null, startAt, endAt, state: ACTIVE|CANCELLED, version, canManage: boolean }. CreatorId internal if required by security/service, not exported. UI lists generic event kinds/date/project context only through authorized setup project collection. Events whose source project itself is CANCELLED disappear from current export. A manually cancelled entered event remains exportable only while its personal/project source is currently authorized and eligible, with the same opaque UID and STATUS:CANCELLED so subscription clients reconcile cancellation. Event date changes keep UID and increment sequence. Task deadline uses committedDueDate when present, otherwise targetDate, without altering either. Active reviewer assignment uses linked task due date; absent dated task/source omitted, never invented. Milestone uses actual targetAt. Completed/cancelled source work excluded from active projection; canceled manually entered events retained internally with state.

## Pure calendar serializer

Export function serializeCalendar(events: CalendarProjection[]): string in apps/api/src/integration-calendar.ts. Emit VCALENDAR VERSION:2.0 PRODID, CALSCALE:GREGORIAN, VEVENT UID/DTSTAMP/LAST-MODIFIED/SEQUENCE/SUMMARY/DTSTART, optional DTEND, STATUS; UTC instants YYYYMMDDTHHMMSSZ, all-day YYYYMMDD with VALUE=DATE, date-only DTEND exclusive next date. Fold lines at <=75 UTF-8 octets without splitting code points, continuation space. Escape backslash, comma, semicolon, newline; no user-controlled component/property injection. Unit tests verify Unicode folding, injection, UID stability and UTC/date-only behavior. serializer implementation may proceed against this settled contract.
