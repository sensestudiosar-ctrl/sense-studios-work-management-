# People — Owner/user walkthrough

7 October 2026. Use the revised low-fidelity prototype. This is a participant guide, not a record of participant results.

## Identify each page's job

Before opening advanced actions, explain what record you would create or inspect here:

| Page | Intended question | Main record |
|---|---|---|
| Time | What work did I actually record? | Time entry / active timer |
| Workforce | Who has planned work on which dates? | Person's dated task allocation |
| Leave / WFH | What absence or WFH request needs action, and what work is affected? | Dated request and configured decision stage |
| Attendance | What is today's punch status and evidence? | OFFICE / SITE punch |

## P01 — Record actual work

Use the Employee sample role for Ananya. Find Time, deliberately select Azure RCP work, inspect timer controls and dated entries. Open an entry's correction/history context. Find the non-project activity path without selecting a project task.

Explain the difference between actual time, planned allocation and attendance. Sample buttons do not establish persisted production records.

## P02 — Inspect planned workload

Use the Owner sample role. Open Ananya from Dashboard workload or Workforce. Inspect the selected employee, dates, task allocations and available schedule/policy explanation. Change the period. Follow a linked task and use contextual Back.

Explain what is known, what configuration is absent, and whether the view invents available hours or silently assigns effort. It should do neither.

## P03 — Review absence and work impact

Find Kabir's LV-013 request for 13 October and its kitchen-task context. Identify the pending state and named current approver. Open the exact canonical decision. Return to Leave/WFH and explain what remains pending.

Find the separate WFH request path. Explain why WFH does not debit leave, why an emergency request still needs impact review, and why requesting cancellation does not immediately undo leave or handovers.

## P04 — Inspect attendance evidence

Find today's OFFICE/SITE punch context. Open the SITE evidence form and identify location, QR, selfie and provisional reason/review context. Find recent punch records and the authorized provisional queue. Inspect retention separately from everyday punching.

Explain why punch records survive selfie expiry and why attendance is not a task timer or continuous location tracking.

## Desktop and mobile observations

Repeat page discovery at a narrow viewport using grouped More → People. Record the first destination chosen, wrong turns, any horizontal scrolling needed, whether the selected record is clear, and whether Back restores the originating selection.

Ask users to explain each page's purpose without coaching. Record completion, hesitation and mistaken expectations. Do not freeze the Workforce label or mobile grouping based only on a personal preference.

## Owner feedback needed

- Can users distinguish actual time, allocated effort, absence and punch status?
- Does “Workforce” predict schedules/capacity/allocations, or does another label perform better during the walkthrough?
- Are daily actions discoverable before advanced policy, export and retention controls?

No business-rule or permission decision is requested by this layout pass. Full production implementation and operational acceptance remain outside this package.
