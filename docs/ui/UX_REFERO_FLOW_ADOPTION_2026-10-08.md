## Suggested validation order

1. **P1 task creation and filter recovery:** run Owner, manager, and employee journeys; verify selected project/task context, retained filters, empty results, and permission-loss behavior.
2. **P1 notifications and review correction:** verify exact source identity, selected-item retention during inbox filtering, and the distinct internal/client/correction/resubmission authorities.
3. **P1 upload and time/leave:** verify partial uploads and retry, exact task/date/unit retention, configured approver routing, and future-date cancellation rules.
4. **P2 settings, reports, training, and security:** validate unsaved/saved state, fixed report schemas and reauthorization, exact training version/human review, and existing account security requirements.
5. **Site/offline:** treat complete offline conflict recovery as an evidence gap. Validate only the current draft, per-file transfer, and explicit sync/conflict behavior that the accepted source and implementation actually support.

These priorities are proposed for a later Owner-selected low-fidelity walkthrough. They do not change approved requirements or implementation scope. This comparison does not claim production validation, UX freeze, complete offline recovery, or acceptance of any recommendation.
