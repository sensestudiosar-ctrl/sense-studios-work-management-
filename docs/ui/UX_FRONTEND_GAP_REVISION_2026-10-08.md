8 October 2026. Prototype only; S18 and bounded S27 remain authorized **IN PROGRESS** in production source acceptance. No Gate B, workflow, permission or backend changes.

## Research decisions before revision

Refero MCP screen metadata and images were inspected. These references inform placement, not Sense Studios rules or styling.

| Issue | Evidence | Change selected | Validation still needed |
|---|---|---|---|
| Training identity and criteria buried in generic actions | [Google Classroom assignment](https://refero.design/pages/503f8c38-8c8f-46fd-bdfe-c2000c9f40c5) | Separate assignment evidence/criteria from assignee, reviewer, version and current action | Can trainee and reviewer identify their next action without assistance? |
| Assistance can look like an automatic decision | [Cycle validation](https://refero.design/pages/b5ecf71b-69a5-4dc3-b11b-5ca8a20e46c9) and [Parallel source evidence](https://refero.design/pages/cdafc3c4-560e-4d35-a4ad-274c5b807fa9) | Group facts and unavailable factors; retain reasoned human decisions separately from the ordinary domain action | Does accepting evidence clearly leave task ownership unchanged? |
| Upload progress and file availability are conflated | [Lemon Squeezy upload](https://refero.design/pages/7b497600-7aa5-4f77-a0e2-4b398844cc33) | Show an exact upload record, retry and explicit finalization before file availability | Can users distinguish upload, finalized file, issue and recipient receipt? |
| Advanced task actions lack an inspectable home | Previously inspected Linear/Wrike task references in the existing research package | Keep exact task identity, dependency, date request and configuration in task context | Can users return to the same task and filter after inspecting a dependency? |
