## Exact failure and root cause

The latest failed preflight reached `Invoke-MwStoppedSafety`. It queried `Win32_Process` for both `postgres.exe` and `pg_ctl.exe`, then required a nonempty `CommandLine` for every returned process before attempting to determine whether it referenced the retained directory. Therefore a `pg_ctl.exe` belonging to an unrelated Windows service could fail the data-directory ownership guard. It also had no alternate classification when a server process's CIM `ExecutablePath` and `CommandLine` fields were unavailable.

The recorded error was generated by that explicit null/whitespace check after process enumeration. The old run did not save the offending PID or the individual CIM field values, so its particular blank cannot now be attributed to process exit versus metadata access. A current read-only host query confirms the metadata-access case exists: CIM returns live `postgres.exe`/`pg_ctl.exe` rows with PIDs and creation dates but empty executable, command-line and owner fields. `Get-Process` likewise reports empty executable paths for those entries. This is not a process-enumeration failure in the inspected host session. Separately, the restricted Codex command sandbox cannot query CIM at all (`Access to a CIM resource was not available to the client`) and sees only three local processes; it is not a valid host-ownership context.

## Ownership rule now implemented

For a stopped cluster, the preflight first validates the matching `postmaster.pid` directory/address/port/readiness fields and parsed PID, then confirms that exact PID is absent. It never edits the PID file. A live recorded PID or contradictory PID fields stop the run.

For every enumerated `postgres.exe`, readable process `-D` arguments are used directly. When process command/executable metadata is unavailable, the script may classify it only by walking an available PID/parent/creation-time chain to the matching running Windows service and parsing that service's configured `pg_ctl.exe -D` directory. A service pointed at the retained directory blocks startup. A different explicit directory is recorded as unrelated evidence. A missing process list, incomplete ancestry, unavailable service configuration, invalid chronology or unclassifiable candidate returns BLOCKED. `pg_ctl.exe` alone is not treated as a server process owner, but is retained as ancestry evidence. Port absence is never used by itself to establish directory ownership.

Running-cluster validation continues to require the retained PID, process identity/owner/creation information, exact listener ownership, disk system identifier and independent read-only SQL checks for host, port, data directory, system identifier and disposable-target absence. Any unavailable target identity still blocks; this change does not turn unknown target metadata into a pass.
