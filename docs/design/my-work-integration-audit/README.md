## 3. Missing functionality and dependencies

The full target cannot honestly be delivered as CSS-only work under unchanged APIs. The following are **not authorized backend work** and must be deferred, narrowed or separately scoped:

1. Canonical cross-functional teams, overlapping membership and a designated team leader. Existing home teams and project assignment rosters can be reused without declaring a new entity.
2. Exact compound My Work metrics and global filtering/sorting for unsupported predicates. Existing supported query totals are reusable; exhaustive client aggregation would require complete pagination, current authorization, deduplication and consistency verification and is not accepted by this audit as a substitute aggregate contract.
3. Complete row-level participant/current assigner/reviewer projections where current list/setup data cannot provide them. Keep creator, current primary owner, collaborators and round reviewer distinct.
4. A No-date target bucket containing real tasks; targetDate is non-null (`apps/api/prisma/schema.prisma:275`). Changing it would violate this frontend-only boundary.
5. Cross-device saved task views, private task visibility, dedicated drawing requests, and combined atomic create/upload/reminder/reviewer behavior. No second model or guessed command is proposed.
6. Exact task-linked pending-upload totals and uniform cached/offline My Work. Existing site offline infrastructure does not prove these broader capabilities.

Real integration prerequisites include authenticated CSRF/session handling, authorized setup labels, current task versions/capabilities, exact review/file identifiers, complete pagination, independent-source errors, and explicit organizational calendar/date definitions. No demo fixture may enter a production data path.

Staff `all` is the service's authorized union of personal/collaboration, permitted reporting-tree nonproject work and explicitly managed projects, not every task involving any team member. Ordinary progress remains with the primary owner or Owner; a Leader's oversight does not grant Start/Wait/Resume/Complete (`task.service.ts:359`, `PERMISSIONS.md:89`). Review authority remains separate; Owner organization authority does not make the Owner an eligible independent STAFF reviewer (`PERMISSIONS.md:119`). Required effective primary ownership and conditional project eligibility remain service-enforced even though `ownerEmployeeId` is optional in the request schema for self-creation.
