## Scalability risks requiring measurement

`TaskService.attention` scans eligible task pages and loads complete detail for each candidate before slicing its response. `ReviewService.inbox` loads candidate rounds, authorizes/projects each and paginates the resulting array in memory. They preserve per-record access checks, but work can grow with the total candidate population rather than the requested page size. Task attention also spans multiple transactions, so count/page consistency under concurrent changes needs explicit tests. These are source-observed risks, not measured latency failures or demonstrated access leaks. Optimize only with equivalent authorization and count-membership tests; never replace policy-filtered counts with raw table counts.
