# Feature-parity preservation matrix

25 October 2026 · Deployed baseline `70b047cd57af5d4a755e45c5c99b06e4039a46c8`. **Design mapping is not runtime proof of an unbuilt redesign.**

This matrix enumerates 409 user-capability obligations across 42 families. The companion endpoint register maps all374 handler declarations, and DEPLOYED_CAPABILITY_INVENTORY.json indexes all1694 button/link/form/input/select/disclosure declarations and all43 deployed Route declarations, including catch-alls. A rendered declaration can expand dynamically into many controls; static counts are not executed UI coverage.

## Preservation contract

1. Retain every accepted owning route/component/action while its presentation is changed incrementally. Existing deep links are the fallback until a replacement passes its per-row test.
2. The matrix covers user actions and read states. Administrative/service-only handlers in the endpoint register remain API/system operations; their existence does not justify inventing a UI action.
3. Every row retains current server permission, Branch/assignment/reporting scope, state/version/reason/evidence constraints and supported recovery. Disclosure changes location/visibility only.
4. Each PAR case must prove current versus proposed discovery, permitted action, denied scope/state, exceptional outcome, desktop/tablet/phone and keyboard access. Rows with absent roles/records are BLOCKED, never passed by a demo.
5. No feature is removed because it is rare. Unsupported prototype actions are marked excluded fixture behavior, not added product capabilities. Current unaccepted checkout changes are preserved but not silently promoted.
6. Before reducing the legacy workspace, verify CRM/admin and every contained operation through its new entry. Retain `/workspace` until then.

## Full declaration evidence

[Endpoint-level register](ENDPOINT_PARITY_REGISTER.md) supplies exact method/path/handler/file/line for every deployed handler. Controller paths are source-relative; the application supplies its existing `/api/v1` global prefix. `FEATURE_PARITY_MATRIX.json` includes endpoint-family cross-references for each user row. A family reference narrows review; it does not assert every operation in that family is the same command.

`DEPLOYED_CAPABILITY_INVENTORY.json` preserves exact UI declaration locations/attributes and dynamic-label expressions, so conditional and uncommon controls cannot disappear just because they were absent from an audit screenshot. Unresolved dynamic data/state combinations require runtime cases. The complete current accepted source stays the reference, not only this summarized label list.
