## Adoption rules

Keep one decision ledger per component/state: exact reference/hash → deployed existing component/route → discrepancy → accepted adaptation → required tests → status. Reuse approved screen sections/components where applicable; never relaunch a broad aesthetic exploration as a prerequisite. Visual-only changes must still preserve all domain actions and full responsive/keyboard behavior.

The future connected prototype links these existing reference structures using one shared sample object graph. It does not merge their scripts into a new independent product, reuse real accounts, connect to live APIs or alter current React code. Prototype construction remains separately gated. See PROTOTYPE_ROADMAP.

Fidelity has two independent outcomes: **Visual fidelity** and **Functional/accessibility reliability**. A visual pass cannot waive another failure. Existing `docs/design/PROTOTYPE_FIDELITY_POLICY.md` requires equivalent actual/reference states, retained screenshots and Owner review; this revision adds the Owner's explicit priority that accessibility/function/responsive correctness wins where a reference conflicts.
