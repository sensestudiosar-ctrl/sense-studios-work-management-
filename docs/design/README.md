## What matters most

1. **Validate the current baseline before further propagation.** New Task/Project/Settings/Workforce work already exists with runtime acceptance pending; stale absent-feature tables must not drive duplicate implementation.
2. **Make scope and continuity dependable.** Preserve owning branch, canonical object, filtered worklist and contextual mobile return.
3. **Make decisions evidence-first.** Task completion, internal review, client item/final batch, Site verification/closure and nonbinding assistance have different authorities.
4. **Make data states truthful.** Missing/denied/insufficient/offline differs from zero or complete. Source cards and report manifests retain authorization/provenance.
5. **Make accessibility part of the foundation.** Proposed stronger text/focus/control boundaries address calculated current contrast gaps; actual rendered acceptance remains future work.

UX changes improve finding work, comprehension, decision confidence, task continuity or recovery. Cosmetic changes align title/icon/radius/spacing appearance and are separately ranked. Accessibility and permission/evidence-state clarity are UX, not optional polish.
