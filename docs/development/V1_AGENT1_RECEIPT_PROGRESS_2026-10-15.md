A closed/advanced parent never causes a second child on replay. First attempts retain all existing creation/parent/project/participant/plan/capacity checks; the receipt commits with the task's ordinary evidence and child link/parent increment. Rejected commands do not insert a receipt.
- Shared composer creates retry keys and preserves the exact submitted command on network/server/malformed-success uncertainty. It disables editing/new submit and offers explicit Check creation result with the same key/body, including acknowledged capacity commands. No automatic retry or cross-account draft storage. Confirmed ordinary creation opens its canonical ID; child creation validates `{ task, parentVersion }`, refreshes its parent and exposes the canonical child ID. Leaving an unresolved request requires an explicit warning that the task may exist and the in-memory recovery request will be lost. Reload/restart recovery is not promised.
- Scoped touch/focus treatment gives recovery keyboard focus and a44px minimum button. Shared disabled fieldsets prevent pending/uncertain fields from changing while preserving the form layout. Existing valid success text and description-boundary assertions remain; an old child mock returning an ordinary task was corrected to the real child response shape.
