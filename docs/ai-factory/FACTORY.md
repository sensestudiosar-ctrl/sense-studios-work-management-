automation routine. It is the single source of operational policy for the
factory. Where it conflicts with the Owner's live instruction, the Owner's
instruction wins and the conflict is recorded in
`docs/ai-factory/DECISIONS.md`. Where it conflicts with `AGENTS.md` or
`CLAUDE.md` on *application* behavior, the application docs win — this file
only governs *factory* behavior.

## 5. Pipeline for every approved issue

DISCOVER → INVESTIGATE → RESEARCH → SPECIFY → IMPLEMENT → TEST → REVIEW →
PREPARE PR → CAPTURE LESSONS

1. **Select** highest-priority *approved, eligible* issue; check holds,
   dependencies, risk, and no duplicate ownership (lease lock, §7).
2. **Investigate** affected files + current behavior on the canonical app.
3. **Research** (UI/UX work only): Refero / UI/UX Pro Max / approved demos.
4. **Specify** scope, acceptance criteria, files, backend impact, tests,
   regression risk. Escalate only if it exceeds prior authorization.
5. **Implement** in an isolated branch/worktree; smallest correct change.
6. **Test** typecheck → lint → build → unit → integration → Playwright →
   accessibility. Never weaken a failing test.
7. **Review** by an *independent* agent (not the implementer).
8. **Prepare PR** (draft): issue ref, summary, changed files, evidence,
   test results, risks, rollback. **Never auto-merge.**
9. **Record lessons** in `docs/ai-factory/LESSONS.md` + metrics.

## 6. Self-improvement (OBSERVE → MEASURE → DIAGNOSE → PROPOSE →
EVALUATE → APPROVE → ADOPT → MONITOR)

- Track real measured metrics only (no artificial scores): workflow pass
  rate, build success, regression failures, escaped defects, reopened
  issues, flakiness, accessibility failures, time-to-resolve, rework,
  coordination failures, cost-per-accepted-change. See `docs/ai-factory/METRICS.md`.
- Root-cause classification taxonomy lives in `docs/ai-factory/RCA.md`.
- Procedural improvements are adopted only after evaluation against a
  baseline. Factory self-modification of *non-executable records/lessons*
  is autonomous; changes to agent permissions, critical instructions,
  executable hooks, CI, dependencies, security, or deployment settings
  go through isolated change → test → independent review → Owner approval.
  Full history in `docs/ai-factory/CHANGELOG_FACTORY.md`.

## 7. Durable checkpoints and recovery

Live checkpoint JSON records are local/ignored and privately backed up. Set a unique stable `FACTORY_WORKER_ID` per worker; lease mutations require the matching live owner. Cross-process updates use a local mutex and atomic JSON replacement. See RECOVERY.md for corrected verification claims. Scheduler activation remains a separate unverified action.

- Every significant task writes a machine-readable record to
  `docs/ai-factory/checkpoints/` via `scripts/factory/checkpoint.mjs`.
- State machine: QUEUED → RUNNING → CHECKPOINTED → PAUSED → RECOVERABLE →
  RESUMING → VERIFIED → AWAITING_APPROVAL → COMPLETED, plus BLOCKED/FAILED.
- On each recovery run: read state → confirm not already done → check
  locks → confirm usage eligibility → confirm repo/branch → restore last
  checkpoint → revalidate assumptions → continue from next safe step →
  verify → update Linear/issue + checkpoint. See `docs/ai-factory/RECOVERY.md`.
- Idempotency: issue-specific leases with expiration; check whether an
  operation already succeeded before retrying; never replay irreversible
  actions, duplicate branches/PRs/comments/issues.
- Bounded retries with backoff; escalate persistent failures; never bypass
  usage limits or enable paid fallback.

## 8. Unattended operations (schedules)

Configured via `mcp__scheduled-tasks__create_scheduled_task`, Asia/Kolkata:

- **Nightly development** — recover unfinished, then one low-risk approved
  issue; tests + draft PR; update status.
- **Daily quality audit** — CI failures, regressions, stale issues,
  factory health. Skip expensive browser audits when nothing relevant changed.
- **Recovery / resumption** — run the checkpoint state machine; respect
  provider retry times.
- **Weekly retrospective** — completed/open trends, repeated mistakes,
  process improvements, efficiency, cost, next priorities.

Schedules only run while a session/app is available; a missed job fires on
next launch. Document this honestly — the machine must be reachable.

## 9. Cost optimization

- Limited concurrency, targeted searches over whole-repo rereads, cache
  verified research, reuse approved design guidance, fast tests before full
  regression, affordable models for bounded work, no repeated recovery
  attempts that cannot succeed before reset, stop nonessential automation
  when limits/budgets hit. No unnecessary paid infrastructure.

## 10. Reporting

The factory reports its actual state — PASS/FAIL/BLOCKED/NOT-TESTED with
evidence. Never claim a check passed that wasn't run, a tool used that
wasn't invoked, or a capability operational without end-to-end verification.
